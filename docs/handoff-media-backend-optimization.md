# Backend Handoff: Media Delivery & Cache Optimization Recommendations

* **Audience:** Backend & Database Engineers (Cloudflare Workers, Hono, D1)
* **Date:** 2026-11-16
* **Status:** Informational / Recommended RFC
* **Frontend Scope Delivered:** 100% frontend optimizations applied (In-flight request deduplication, Carousel lookahead prefetch, WOFF2 migration, React.lazy code-splitting). Zero backend endpoints or schemas were modified.

## 1. Executive Summary

The frontend team has optimized media delivery within `<ProtectedCanvasImage>` and `<Hero>` to eliminate network waterfalls and achieve 0ms carousel transitions via in-memory Blob caching.

To unlock maximum edge performance and native browser preload scanner acceleration without compromising anti-scraping protections, we recommend two backend adjustments in `backend/src/index.ts`.

---

## 2. Recommendation A: Allow Same-Origin Browser Preloads for Hashed Assets

### Current Behavior:
In `backend/src/index.ts`, the media protection middleware requires:
```typescript
if (isProtectedImage) {
  const isAuthorizedClient = await isAuthorizedMediaRequest(c, fileKey)
  if (!isAuthorizedClient) {
    return c.redirect('/', 302)
  }
}
```
Where `isAuthorizedMediaRequest` enforces `c.req.header('X-R59-Client') === 'media-viewer'`.

### The Problem:
Browser HTML preloads (`<link rel="preload" as="image" href="...">`) are generated by the browser's native C++ Preload Scanner before any JavaScript executes. However, standard HTML `<link rel="preload">` cannot attach custom HTTP headers like `X-R59-Client`. As a result, the Cloudflare Worker intercepts the preload request, fails the header check, and returns a `302 Redirect` to `/`.

### Proposed Backend Solution:
Allow same-origin image preloads by verifying standard browser Fetch Metadata headers (`Sec-Fetch-Dest` and `Sec-Fetch-Site`):
```typescript
const fetchDest = c.req.header('Sec-Fetch-Dest')
const fetchSite = c.req.header('Sec-Fetch-Site')

// Allow same-origin browser image requests for hashed static assets
if (
  pathname.startsWith('/assets/') &&
  fetchSite === 'same-origin' &&
  (fetchDest === 'image' || fetchDest === 'empty')
) {
  return true;
}
```
* **Security guarantee:** Cross-site embedding (`Sec-Fetch-Site: cross-site`) remains completely blocked with `403 Forbidden`. Direct address-bar navigation (`Sec-Fetch-Dest: document`) remains blocked with `302 Redirect`. Only same-origin requests originating from our own domain are permitted.

## 3. Recommendation B: Cloudflare Edge Cache-Control for Media Endpoints

### Current Behavior:
Dynamic media served from Cloudflare D1 via `/api/media/:key` is fetched on demand.

### Proposed Backend Solution:
Ensure responses for `/api/media/:key` and static assets include immutable cache directives for Cloudflare's Edge Cache:
```typescript
c.header('Cache-Control', 'public, max-age=31536000, immutable')
c.header('CDN-Cache-Control', 'max-age=31536000')
```
* **Performance gain:** Repeated requests for portfolio photos will be served from Cloudflare's worldwide CDN memory in < 20ms instead of hitting D1 queries.
